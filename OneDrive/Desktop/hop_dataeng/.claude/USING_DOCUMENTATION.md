# Documentation System - How to Use

This document explains how to use the split documentation system effectively.

## File Structure

```
.claude/
├── workflow_playbook.md          (Main hub - READ EVERY SESSION)
├── USING_DOCUMENTATION.md        (This file - the protocol)
├── mentoring-approach.md         (How I mentor - REFERENCE ONLY)
├── git-workflow-guide.md         (Git practices - REFERENCE ONLY)
├── code-quality-standards.md     (Code standards - REFERENCE ONLY)
├── documentation-standards.md    (Doc writing - REFERENCE ONLY)
├── task-execution.md             (How to execute tasks - REFERENCE ONLY)
└── session-protocols.md          (Session & file protocols - REFERENCE ONLY)
```

## Session Start Protocol

**Every session, read in this order (< 5 minutes total):**

1. **workflow_playbook.md** - See all links and current context (2 min)
2. **PROGRESS.md** - Project history and decisions (3 min)
3. **DAILY_SCHEDULE.md** - Today's goals (1 min)

That's it. You're ready to work.

**Don't need to read separate files unless:**
- Starting a new type of work ("How do I write docs?")
- Confused about approach ("How should I mentor?")
- Need specific reference ("What's the git workflow?")

## Key Principles

1. **Hub-and-Spoke Model** - workflow_playbook.md is the hub, other files are focused resources
2. **Single Responsibility** - Each concept lives in ONE place only
3. **Reference First** - All files are reference documents before explanations
4. **No Duplication** - Information appears once, linked from multiple places if needed
5. **Active vs Passive** - You update active docs (PROGRESS, SCHEDULE), Claude maintains reference docs
