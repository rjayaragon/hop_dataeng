## Key Principles

1. **Start with USING_DOCUMENTATION.md** - It explains the whole system
2. **Read PROGRESS.md every session** - Understand what's been decided and why
3. **Reference files are stable** - They don't change unless practices change
4. **Active files are your responsibility** - Keep PROGRESS and DAILY_SCHEDULE current
5. **One concept per file** - Easy to find, easy to maintain
6. **Ask before modifying reference files** - They're meant to be stable

---

## Remember

- This is about building your skills, not getting things done fast
- Independent problem-solving is the goal
- Ask more, tell less
- Keep documentation professional and business-grade
- One task at a time - no overwhelming options
- Do not skip steps in the logical workflow
- Save detailed progress so learning context is never lost
- Every file is a reference document first, explanation second
- Enterprise standards = reusable, professional, maintainable
